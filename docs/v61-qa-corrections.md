# V61 — corrections issues des vérifications

- **Commande masquée après victoire.** La notification globale interceptait le clic sur MENU. Le statut, sans contrôle interactif, laisse désormais passer les pointeurs. Pendant The Pit, il est aussi déplacé pour ne pas recouvrir visuellement MENU ni les boutons tactiles. La recette vérifie leurs rectangles réels et clique le bouton pendant que le statut est visible.
- **Extracteur156 masqué par le sol.** Le cadrage isolé initial utilisait un centre vertical différent du jeu. La mesure en combat (`centerY362`, zoom1,5887) a été ajoutée au harnais. L’extracteur est replacé sur la partie haute de la façade d’une tour, sans agrandissement artificiel. Les autres motifs et les pixels natifs restent inchangés.
- **Mesure insuffisante de la traversée144.** L’observateur dédupliquait ses échantillons par pose, donc perdait les déplacements entre deux dessins. Sa clé inclut désormais `travelX`. Les assertions conservent leur exigence de positions multiples, bornées et masquées ; aucun déplacement du jeu n’a été changé pour satisfaire le test.
- **Observation mixte au changement de manche185.** Un échantillon pouvait lire le nouveau DOM et la dernière image canvas du round précédent, entre le commit React et l’effet de rendu. Le contrôle accepte uniquement une dernière pose d’une occurrence prouvée du round précédent, pendant un seul échantillon, suivi immédiatement d’un état inactif au tick courant. Trois tests rejettent les cas plus larges, notamment un événement du round courant pendant l’introduction ou le compte à rebours. Le directeur de jeu est inchangé.
- **CSS obsolète dans la première publication V61.** Le déploiement `9e0984f` était READY et servait correctement les 29 PNG, mais sa CSS publique omettait les trois règles de notification présentes dans le commit et dans le build local. Un vrai duel public a révélé le chevauchement avec MENU. La compilation Vercel est alignée sur `next build --webpack`, déjà utilisée par la recette locale ; un contrôle de la CSS compilée doit désormais retrouver les trois règles avant qu’un build puisse réussir. Le mécanisme exact ayant livré l’ancien CSS n’est pas établi. Le premier échec est conservé dans `docs/v61-public-story-initial-failure.json` ; seule une nouvelle recette publique réussie peut fermer ce défaut.

Les échecs initiaux sont conservés sous `work-local/v61/qa/`. Seules les relances réussies avec les empreintes de sources finales alimentent `docs/v61-final-qa.json`. Les contrôles publics restent enregistrés séparément après déploiement.
