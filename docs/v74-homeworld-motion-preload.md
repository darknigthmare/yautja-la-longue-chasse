# Homeworld V74 — préparation des animations natives

`useHomeworldMotionAssetsV74({youth})` expose `ready`, `error`, `loaded`, `total` et `retry`. Il sélectionne les sources réellement utilisées par les frames : huit PNG civils, auxquels s’ajoutent seize PNG du jeune lorsque `youth=true`. Les anciennes sources et les pixels ne sont pas transformés. Le hook reste initialement bloqué pendant le SSR ; le propriétaire doit geler ses contrôles et sa simulation jusqu’à `ready=true`.

Chaque image est chargée et décodée avec `Image.decode()`, puis ses dimensions naturelles sont comparées aux métadonnées. Une source absente, non décodable ou de mauvaises dimensions produit une erreur française et conserve `ready=false`. Les autres chargements peuvent terminer et mettre à jour le compteur, sans masquer l’erreur.

« Réessayer » rend immédiatement le hook non prêt et recharge les URL PNG originales avec `fetch(...,{cache:'reload'})`. Les réponses sont intégralement consommées puis les mêmes URL sont décodées par `Image`. Un suffixe de requête seul préparerait une autre clé de cache que les backgrounds du renderer ; cette méthode conserve donc les chemins originaux, sans nonce d’horloge ni référence supplémentaire à un bitmap.

Le nettoyage ignore les promesses après démontage, annule les requêtes de relance et retire le `src` des images encore pendantes. Après succès, les images locales sont libérées : aucun registre de refs ou Map d’images décodées n’est gardé par le hook. Les seuls tableaux persistants contiennent les métadonnées. Le module n’a ni rAF, ni horloge de simulation, ni accès à une sauvegarde, ni appel backend.

Les huit tests vérifient les dimensions PNG réelles, les deux jeux de sources, le SSR initial bloqué, la progression jusqu’au dernier décodage, une source absente, une dimension incompatible, la relance des chemins originaux et les deux annulations après démontage. ESLint ciblé passe. Ces tests utilisent un environnement image/réseau contrôlé pour les erreurs ; ils ne remplacent pas la validation du navigateur.

`scripts/verify-homeworld-motion-assets-v74.mjs` a passé cette validation sur le build V74 final local : **3 contrôles, 3 captures**, rapport `work-local/v74/qa/motion-assets-local/report.json`. Un vrai PNG de direction opposée est bloqué dans le navigateur. La cité reste immobile avec son ancien idle et une erreur lisible, puis le bouton de relance recharge le PNG original, préserve la sauvegarde et rétablit le premier pas natif. Les requêtes attestent le premier abort puis le rechargement du même chemin, sans nonce. La position, l’horloge de cité, la distance de marche et les octets de sauvegarde restent figés pendant l’erreur ; le premier pas réellement joué reprend ensuite sur une source décodée aux dimensions attendues. Aucune erreur JavaScript n’a été observée. Cette validation concerne `http://127.0.0.1:4192`, pas encore une publication.

Variables : `V74_MOTION_ASSETS_QA_URL`, `V74_MOTION_ASSETS_QA_OUTPUT` et `YAUTJA_QA_EXPECTED_VERSION`. Le profil isolé prépare les prérequis d’accueil déjà validés par le modèle ; la panne est une vraie requête PNG bloquée par le navigateur, sans remplacement des fonctions de simulation.
