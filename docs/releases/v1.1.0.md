# La Longue Chasse — version 1.1.0

## Repérer la version du jeu

Le menu principal et l'en-tête du jeu affichent `v1.1.0` ainsi qu'un identifiant
de build de huit caractères. Cet identifiant provient du commit réellement
compilé par Vercel, GitHub Actions ou Git local. Un export de sources sans Git
affiche `local`. Le titre de l'onglet indique aussi la version du jeu.

La version de l'application est définie dans `app/game/buildInfo.ts`. Elle est
distincte des numéros historiques des lots de contenu et du format des
sauvegardes. Les dépendances verrouillées restent inchangées.

## Menu principal

| Rubrique | Commandes |
| --- | --- |
| Campagne | Continuer, Nouvelle partie, Charger une partie, Importer une campagne JSON |
| Modes de jeu | The Pit, Game Reserve Planet, Guerres des clans |
| Archives & chroniques | Archives visuelles, récits et Mausolée |
| Système | Compte et synchronisation, actualisation des archives, plein écran si disponible |

Les touches fléchées et la manette permettent de naviguer. Entrée ou le bouton A
valident ; Échap, le bouton B ou Retour remontent d'un niveau. Le focus revient
sur la commande d'origine après une annulation ou un retour. Les scènes externes
retrouvent leur rubrique d'entrée au retour dans le menu.

Les cinq parties, dix sauvegardes manuelles et deux sauvegardes automatiques par
partie restent disponibles. Les confirmations de remplacement, protections des
archives et avertissements de spoilers conservent leur rôle.

## Corrections de reprise et vérifications

- L'import d'une campagne dont l'identité de propriétaire est absente affiche
  le refus approprié. Aucun propriétaire n'est inventé et aucune archive locale
  n'est modifiée par ce refus.
- Les tests de reprise d'une chasse vérifient que son gantelet reste celui du
  lancement et qu'une nouvelle chasse prend l'équipement nouvellement choisi.
- Les régressions Homeworld suivent la route actuelle du convoi et les
  migrations vers le format de sauvegarde courant, avec protection contre les
  anciens clients.
- Les audits de l'application, des modèles et des publications historiques
  s'exécutent dans trois groupes indépendants, réunis par un résultat obligatoire.
- Les certificats et classeurs datés sont contrôlés dans leurs publications Git
  exactes. Leurs images, données et assertions originales restent intactes ;
  ces preuves passées ne sont pas présentées comme des tests du jeu actuel.

Les détails des réparations historiques sont conservés dans
`docs/qa/history-audit-20261103.md` et
`docs/v113-production-history-routing.md`. Les contrôles navigateur courants
s'exécutent séparément sur le code présent.
