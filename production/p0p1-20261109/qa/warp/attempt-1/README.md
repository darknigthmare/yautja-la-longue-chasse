# Recette native du module WARP

17 contrôles réussis sur le vrai `/dev?lieu=warp-module` servi par Next : trois formats1440/390/320, marche au clavier, arrêt, sas fermé/ouvert, passage des deux salles, prérequis console et mémoire, calibration locale, retour et sortie. Les trois comparaisons des archives existantes sont identiques à l’octet.

Le script `scripts/qa-warp-module-p0p1-20261109.mjs` ne remplace ni DOM ni moteur. Ses boutons déclenchent les parcours et les actions du composant réel. Un témoin d’archive étrangère est déclaré et conservé ; aucune progression gagnée n’est préparée. Les scripts JavaScript servis sont comparés aux vrais octets `.next`, et l’empreinte des sources app/desktop reste identique avant/après.

Les quatre PNG originaux ont été ouverts par root. Le rapport brut reste dans `report.browser-run.json`; `report.json` ajoute seulement cette inspection et le lien au reçu original. Ce n’est ni une campagne WARP complète, ni un contrôle sur manette physique, ni une revue canonique humaine.
