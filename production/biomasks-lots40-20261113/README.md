# Masques sourcés · lots de 40 par domaine

Quatre domaines sont traités en parallèle : films, jeux vidéo, comics/romans et sources licenciées. **40 est une capacité maximale par domaine, jamais un nombre de masques déclaré produit.** Le manifeste, la galerie et le nouveau classeur distinguent les références qualifiées, les paires A/B acceptées, les C techniques terminées, les blocages, les doublons et les alias. Aucun design n’est inventé pour remplir un lot ; un nom ou une description de roman sans visuel ne prouve pas une forme.

Le relevé final contient **161 dossiers documentaires** : films 40, jeux 41, comics/romans 40 et sources licenciées 40. Le dossier jeux supplémentaire est la tentative de réparation Vapor rejetée par root, hors des quatre audits documentaires de 40. La capacité 40 limite les études éligibles par domaine ; elle ne plafonne pas le nombre de lignes documentaires, bloquées ou déjà couvertes.

Ce gel sélectionne **46 études provisoires A/B**, soit 92 PNG ImageGen natifs, et 46 C techniques nouvelles sans ImageGen ; 99 dossiers restent bloqués et 16 sont des doublons exactement couverts. Ces représentations d’éditions, variantes ou vues ne sont pas 46 nouvelles géométries certifiées. Les 46 exigences canoniques historiques restent un suivi indépendant, sans fermeture automatique.

Chaque représentation acceptée conserve ses références R à octets identiques. A est une nouvelle étude isolée créée par ImageGen depuis ces R, pas une copie exacte de leurs pixels. B est un rendu ImageGen distinct de la même représentation, avec une présentation PHG. C est une dérivée technique de B : `Y=floor((2126R+7152G+722B+5000)/10000)`, puis `(Y,Y,Y,alphaB)` sur chaque pixel RGBA8 décodé, y compris les RGB sous alpha nul. La méthode `srgb8-rec709-luma-v1` utilise les octets sRGB encodés, sans linéarisation. Chaque alpha et le cadre natif restent identiques. C ne constitue ni un albédo non éclairé, ni une matière PBR, ni un UV ou une intégration runtime.

Une édition ou peinture réellement sourcée peut être reliée à une famille existante par `maskFamily` et `representationOf`. `newCanonicalGeometry:false` indique une absence de certification nouvelle et ne prouve pas un mesh identique. Le compteur `sharedGeometryStudies` utilise uniquement `sharedGeometryStudy:true` explicite et respecte false ; `editionStudies` compte les études d’édition déclarées. `canonicalGeometryCertified` reste séparé à zéro. Aucune identité de mesh ne se déduit de la couleur ou du nombre de représentations. Un alias strictement identique reste dédupliqué. Une édition NECA ou une illustration fournie n’est pas une certification du masque exact d’un film, jeu ou comic. Aucune génération, revue automatique, neutralisation ou mesure ne ferme une exigence canonique ou ne devient une validation artistique humaine.

La tentative de révision Vapor a été rejetée : les yeux trop hauts et la mâchoire trop longue ne permettaient pas de retenir une version fidèle, malgré un ratio global amélioré. Aucune nouvelle paire Vapor A/B/C n’est acceptée dans ce lot. Le dossier bloqué conserve son lien avec `predator_17` ; tous les anciens PNG/C provisoires et leur réserve restent inchangés.

Le baseline main `2b96849482b3b16f1fe3c2040ea23a254bc4f897` protège **870 fichiers, 127 anciens XLSX, 151 PNG ImageGen et 69 C techniques**, sur sept lots précédents. Le snapshot est épinglé par un SHA littéral dans le builder, le selector et les vérificateurs. Les 46 exigences canoniques historiques restent ouvertes ; de nouvelles études d’édition peuvent y être reliées sans clôture. Aucun ancien pack ni fichier de l’application n’est modifié.

Les preuves documentaires de transport HTTP sont explicitement amendées : 65 fichiers d’en-têtes ont été inspectés, dont 19 contenaient 76 lignes Set-Cookie. Seules ces valeurs ont été masquées ; les originaux privés restent conservés et les correspondances SHA brut/assaini sont documentées dans `inputs/research/transport-header-redactions.json`. Ces en-têtes assainis ne sont donc pas des copies brutes à octets identiques du transport. Aucun pixel, fichier natif R/A/B/C, reçu de génération ou statut de qualification n’a été modifié.

La galerie compare B/C ou A/B/C, propose une échelle visible 300/96 px, des fonds de contrôle et un tiroir A/B/C/R accessible au clavier. La teinte de C est uniquement un aperçu sur canvas : aucun PNG enregistré, aucune source réécrite. Le tableau des dossiers non produits reste consultable par domaine. Toutes les images natives et références conservent leurs octets ; les seules modifications RGB concernent les nouvelles C autorisées.

Les A/B/C natifs restent limités à 16 777 216 pixels par image. Les photographies R officielles peuvent atteindre 67 108 864 pixels (64×1024²) pour préserver les grandes vues de détail, avec lecture séquentielle. Le format et les dimensions sont contrôlés depuis l’en-tête avant le décodage complet ; aucune grande R n’est redimensionnée ou réencodée. La taille du fichier conservé reste soumise au plafond de sélection CI de 2 Gio.

Le module C éprouvé du lot neutral reste inchangé et utilise Sharp 0.35.4 verrouillé ; les fichiers de dépendances sont archivés sous `inputs/reproduction/`. Le générateur refuse l’écrasement d’une C existante. Les deux vérificateurs Python/Pillow ne transforment aucune image et fonctionnent sans les PNG privés ImageGen. Le contrôle indépendant vérifie la formule sur tous les pixels ; une API ciblée sert seulement aux petits négatifs, jamais à faire passer une vérification partielle pour exhaustive.

La CI sélectionne seulement les fichiers littéraux du snapshot, des entrées, des ressources acceptées et des preuves QA indexées. Son plafond est de 3 072 fichiers et 2 Gio pour permettre jusqu’à 160 représentations sourcées et leurs R tout en préservant environ 644 Mo de baseline ; le rapport donne le volume réellement sélectionné. Les catalogues 255/164 sont des métadonnées de recherche : leurs chemins bruts ne provoquent aucun téléchargement de grands répertoires. Les QA sont indexées après gel dans `suivi/qa-evidence.json`, hors entrées du manifeste pour éviter un cycle de hashes entre manifeste et rapports.

Après gel des ressources, du manifeste, du classeur et des captures, `tools/export-review-delivery.py --frozen-manifest-sha <SHA256>` crée un ZIP hors dépôt sous `/tmp/mask-lots40-20261113/`. Il comprend tout le nouveau namespace public, ce README, le nouveau classeur, des captures QA choisies et un `LISEZ_MOI.txt` français avec la commande du serveur HTTP local. Il conserve les chemins relatifs et relit chaque entrée ZIP ainsi que son fichier source pour comparer leurs SHA-256 ; son rapport indique le nombre d’entrées, les octets et le SHA de l’archive. Les origines privées, tentatives rejetées et anciens lots restent exclus. L’option `--qa <chemin-relatif>` peut être répétée pour sélectionner les captures ; quatre vues de la galerie sont proposées par défaut.
